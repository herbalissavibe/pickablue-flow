# Технологический стек и обоснование

## Рекомендуемый стек (showcase: визуал + интерактив)

| Слой | Выбор | Зачем |
|------|--------|--------|
| Сборка и dev-сервер | **Vite 6** + **TypeScript** | Мгновенный HMR, минимальная конфигурация для статического one-pager; проще и быстрее старт, чем полноценный Next для страницы без SSR/ISR. |
| UI | **React 19** | Компонентная модель, экосистема для анимаций и модалок; стандарт для портфолио/showcase. |
| Стили | **Tailwind CSS v4** | Быстрое воссоздание сетки и отступов макета, дизайн-токены через `@theme`, адаптив без отдельного CSS-файла на каждую секцию. |
| Анимации | **Motion** (ex-Framer Motion) | Scroll-linked и entrance-анимации, layout transitions, без низкоуровневого GSAP для типовых кейсов one-pager. |
| Модальные окна / доступность | **Radix UI** (`@radix-ui/react-dialog`) | Focus trap, Escape, aria-modal, совместимость с клавиатурой — критично для fullscreen video modal. |
| Видео в hero | Нативный **`<video>`** | Достаточно для full-bleed фона: `playsInline`, `muted`, `loop`, `poster`; не тянуть тяжёлый video-плеер ради фона. |
| Линтинг / формат | **ESLint 9** + **Prettier** | Единый стиль; опционально **eslint-plugin-jsx-a11y**. |
| Деплой | **Статический хостинг** (Netlify, Vercel, Cloudflare Pages) | `vite build` → SPA/статика; CDN для `mp4`/`webm` или отдельный object storage при росте веса медиа. |

## Почему не Next.js по умолчанию

- Для **одной** лендинговой страницы без динамических маршрутов, без серверных данных и без необходимости SSR **Next добавляет сложность** (кэш, layout rules) при том же итоговом результате (статика).
- Если позже понадобятся **blog**, **i18n routing** или **server actions** — миграция на Next или добавление маршрутов остаётся возможной.

## Почему не Astro «везде»

- **Astro** отлично для контентных сайтов с редкими островками React, но для **плотного интерактива** (несколько модалок с видео, синхронные анимации скролла, сложный hero) проще держать **единое React-дерево** на Vite без границ островков.

## Опциональные дополнения (по мере необходимости)

- **`vite-plugin-svgr`** — если волны/декор как React-компоненты SVG.
- **`@tanstack/react-query`** — обычно **не нужен** для статического one-pager; рассмотреть только при подключении реального API форм.
- **Аналитика** — отложить до продакшена (Plausible, Matomo) через env-флаг.

## Медиа и производительность

1. Два формата: **WebM (VP9)** + **H.264 MP4** fallback.
2. Короткие ролики для hero и модалок; **poster** кадр для LCP.
3. `preload="metadata"` или контролируемый `preload` только для hero после согласия с политикой производительности.
4. При необходимости — вынести крупные файлы на **CDN** с range-requests.

## Версии (ориентиры на момент создания документа)

Зафиксировать в `package.json` при инициализации проекта; ориентир: Node **20+**, npm/pnpm **10+**.
